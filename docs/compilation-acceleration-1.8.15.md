# 1.8.15 本地编译加速

本轮针对“请求持续消耗，但精炼总结推进异常”的已复现缺陷实施修改，不重置全库，不删除原始课件、字幕或人工稿。

## 行为变化

- 字幕审校通过后持久化；同稿同源重试只处理失败／未审块，重新校验缓存结构。来源、稿件、提示词或模型服务身份改变时不沿用无效审校。
- 精炼字幕总结由独立后台线程驱动，不再排在整批旧校对后；每次最多两个新请求后轮转，跨进程课堂锁、取消、播放优先与原文哈希保护仍有效。
- 字幕分稿采用分配后的短预算，尽量在既有上下文上限内一次综合，超长时才分层。最终仍对照全部原始字幕块审校，不截取开头或直接截尾。
- 自动课件同步每轮领取一份课件，每份两个新请求后持久化让出；这是合作调度切片，不是每日／任务调用总额度，也不累计失败次数。已有完成资料不重编。
- Wiki 在没有可执行的课件总结时补齐，不挡住首批正文。旧手工整批接口保持兼容。
- 已保存全页证据不再重新转 PDF 或重绘；部分完成的 PPT 转换 PDF 也按源码版本登记哈希后复用。
- 可保守证明为纯文本的 PDF 页直接保留原生证据，不调用视觉模型；图片、路径绘图、Type3 字体和未知操作仍走整页视觉。来源冲突仍可定向原图复核。
- 结构化编译启用 JSON 模式；只规范明确的引用形式和已完整声明的页码顺序。主题来源映射不强迫逐页点名，实质遗漏交给全输入来源审校，不补造出处。
- 按服务／凭据的不可逆摘要共享本机 SQLite 请求预约，主 App、后台和聊天共同执行 10 RPM、保守 300000 TPM 预约、最多两个在途请求与 429 冷却。长请求续租，崩溃租约会释放；不额外设置每日调用上限。
- 编译连接复用到服务关闭。新增请求级耗时记录，保留排队／开始／结束、模型、阶段、输入输出缓存与缺失计数，最多保留七天／20000 条已结束记录；不保存密钥、地址、提示词或响应。

## 验证

本机完整 Python 回归：1230 项通过、503 子测试通过、1 项跳过。秘密扫描和差异格式检查通过。补充了最后审校超时续编、来源变化失效、队列独立推进、合作切片、跨实例 RPM／TPM／在途租约、429 冷却、纯文本判定及不重复渲染测试。

沙盒完整回归：1228 项通过、503 子测试通过、3 项平台相关跳过。

真实交大 API 隔离验收（不覆盖生产清单）：未完成字幕分4块，9次请求／5个两请求切片，140.68秒，总结679字符；42页真实失败课件复用既有页稿与总结检查点，补做1次完整来源审校，6.64秒，总结2653字符。两者再次恢复均为0请求，原始文件SHA不变，全部请求返回usage。前者输入22779／输出2437 token；后者输入28319／输出15 token（补做审校，非从零生成42页）。不能将此作为从零编译吞吐或固定倍数提升。

验收脚本修正macOS临时目录的符号链接规范化；没有放松生产符号链接安全门。候选打包和安装验收记录将在部署完成后追加，不宣称全库完成。

## 边界与回退

正文保留原文约 30% 软目标和 3000 字符硬上限，原始字幕不裁剪。PPT 宏、外链、嵌入对象的安全拒绝没有放宽，无法安全恢复的来源不会被伪造为完成。

完成稿、人工修改稿和源码哈希检查保持不变。更换 App 前保存原 bundle；回退只切换应用，不删除新旧源文件和检查点。旧校对未删除；独立总结不会等待整批旧校对，但同一课堂正在写入原件时仍避让，避免竞争覆盖。

请求记录位于应用支持目录的 `ai-runtime.sqlite3`，由程序自动创建，无数据库主表迁移。缺失 usage 为未知，缓存量不推定为零。图片预约采用保守估计，上游仍是最终额度权威。

本轮仅本地提交和部署；不推送 GitHub、不创建 PR、不发布 Release。
