# 2.0.1 本地会话中断修复

本轮根据 2026-11-28 的真实 DeepSeek 对话记录修复会话干预、日历参数纠正与循环回复。已发布的 v2.0.0 标签保持原提交；2.0.1 为本地补丁。

## 根因与变更

- 原任务在第 5 个阶段收到日历时间参数错误，第 6 个阶段便强制关闭工具；之后到达的「确认」也无法重新打开日历写入能力。现在最终整理指令只作用于当前请求，补充到达后恢复允许的工具。补充、参数纠正和重复输出纠正共享最多 3 个恢复阶段；即使补充在早期到达，也获得固定恢复额度，原有 16 次模型请求、累计 Token、上下文和总时间预算不重置。
- 第二次尝试把原生日历 ID 改写成不存在的值，又在无工具回复中反复猜 ID；finish_reason=length 自动续写进一步延长了循环。现在在流式输出与完成结果两处检测密集重复，保留已付费片段，丢弃重复内容的续写上下文，最多进行一次纠正请求。连续失败会停止并明确报告未完成范围。
- 日历 schema 显式声明带时区的 ISO 8601 时间，并提供 +08:00 示例；日期解析仍拒绝无时区值。读取日历后把可写 ID 绑定到创建参数的枚举；目标 ID 无效时返回当前可写日历列表，禁止猜测。
- 同轮相同参数的成功学习查询复用已读结果，避免重复检索；实时日程和文件写操作不使用这种缓存。写入仍遵守 UUID 幂等与 revision 冲突检测。
- 停止在非网络工具边界也生效；已经开始的单次原生操作不能当作可撤销操作。网络请求、补充、付费响应与停止沿用已有持久账本。
- 前端接收 response_reset 时清除本任务的旧流正文，保留用户输入和有效工具记录；显示恢复执行与重复输出纠正状态。技术详情不再把受限的阶段数误报为实际模型请求数，完整调用数以 Activity 持久账本为准。原有单个发送／停止按钮继续使用。

## 本机复测入口

`--chat-self-test` 仅在显式启动时进行真实付费请求，使用生产聊天组件、AgentLoop、模型客户端和 EventKit。聊天数据在本机 SQLite 一致性快照中隔离，避免改变原会话与原任务状态；快照保留本轮付费响应供本机排查，不作为产物上传。

可用 `--backend-only` 在原生 AppKit 循环中验证真实后端；`--ui-stop-only` 单独验证首包前停止与切页返回，不创建日程。UI 验收等待对话初始化完成，只选择仍可交互的菜单项，并依据菜单展开状态判断关闭；测试 JavaScript 调用有 10 秒等待上限，无测试请求的窗口启动等待 45 秒后退出。早期自动化脚本的窗口等待与菜单选择失败单独记录，不作为模型循环重现。

默认日历只读。可选的 `--schedule` 是已获用户授权的单项日程 JSON；验收只允许所选日历、相同时间、建模与优化课程与无提醒的新建，并实时查重、原生回读，不创建其他演示事件。`--request-access` 只在原生 App 缺少系统权限时申请完整访问。

安装前暂停新模型请求并等待在途请求排空，正常退出旧 App，备份原 App、SQLite 和设置，核对受保护学习文件，替换后恢复原 AI 开关。部署脚本使用源码目标版本并按安装路径退出 App，避免多个同名验收 App 时退出错误实例。

## 验证边界

这批检查覆盖用户提供的日期参数失败和 ID 循环样本，并覆盖停止、补充及切页恢复；不能据此保证任意模型、任意网络故障和任意长对话均不会失败。重复检测排除代码块，避免把合法重复代码误判为文字循环。Windows 原生真机验证和新版本远端发行不在本轮已完成范围内。
