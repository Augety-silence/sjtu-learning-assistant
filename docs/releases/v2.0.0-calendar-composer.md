# 2.0.0 日历与 AI 对话细节更新

本轮继续使用 React + TypeScript 和独立 2.0 CSS。生产页面仍连接现有控制器、桌面 Bridge、文件提议和 Agent Runtime；示例数据仅在独立验收入口。

| 用户审阅项 | 本轮实现 |
| --- | --- |
| 表头、全天区和时间网格错位 | 共享时间轴与日期列宽，测量实际滚动条占位并补偿；当天数字固定 30px 蓝圈、星期与数字居中 |
| 午夜作业截止挤在底部 | 23:59 与次日 00:00 截止进入对应日全天区，标注 23:59／24:00 截止；保留作业详情与跳转 |
| 红色时间线位置 | 首次定位到当前时间前 150 分钟并按半小时向下取整；03:00 前和 23:00 后不强制定位，时间刷新不拉回手动滚动 |
| Mac 配置平铺 | 点击连接状态在锚定浮层配置目标日历、迁移和断开，保留真实连接链路 |
| 日程编辑过大与原生日期控件 | 460px 编辑窗、起止日期并排、两行备注；应用月历支持选日、月份切换、今天、键盘及最小日期 |
| AI 输入和输出偏移 | 共用滚动区域实际宽度与边界；用户气泡随文字长度收缩并贴右 |
| Trial／修改前确认跳页 | 工作区名向上展开目录、附件和模型配置；修改前确认就地说明真实文件权限 |
| 发送与暂停同时出现 | 运行无草稿显示单暂停；输入补充后切为发送，经现有 `submit → flushSteering → steerAiChatTask` 交给当前 taskId |

复核中另修了两个状态问题：取消后重开恢复完整草稿，包括未填写标题时的原起止日期、全天、地点、备注和提醒；旧本机全天日程迁移到 Mac 保留全天属性。草稿是否存在用独立缓存判断，不能以标题是否非空判断。

日历工具 `alarms` 的单位、范围和示例已写入共享 schema 与错误提示：提前 30 分钟为 `[-1800]`，无提醒为 `[]`，开始时为 `[0]`，最多五项、范围 `[-604800, 0]` 秒。不会将对象、字符串或正分钟数默默转换后写入。实际 App 身份的日历验收脚本改为测试提前 30 分钟提醒。
