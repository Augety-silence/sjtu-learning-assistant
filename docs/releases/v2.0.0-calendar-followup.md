## 本轮实现

Activity 的 details 恢复纵向块结构，summary 单独横向排列；Logo 固定 28px，工具说明与返回结果在侧栏内换行，轨迹独立滚动。运行时停止与补充按钮留在输入栏右端。

同步面板查询真实 DesktopScheduler 状态，展示实际周期和上次成功时间。“立即同步学习数据”与“基础 MD 转换”分开；编译进度嵌入同一面板，继续按每 5 秒读取后台实际状态，不再嵌套第二个浮窗。学习数据仍按原自动同步策略执行，课件编译暂停/继续保留原知识库入口。

播放器保持 16:9，倍速、全屏、PPT、字幕开关及讲义/字幕/课件页签在框内。工具栏在底部留出完整原生播放控制区；展开学习面板时字幕移到上方可见区域。字幕逐段显示时间标签、标记当前片段，点击或 Enter / Space 跳转到实际播放时间，正文仍可选择。经典模式保留原字幕文本结构。未选择录像时不展开无意义的工具面板。生产流地址和字幕仍由原接口获得；验收流和示例轨迹只存在 src/test，不进入生产构建。

Mac 日历服务使用 EventKit、应用完整访问授权和系统变更通知。日程页面按 5 秒回读系统日历；连接后新建/编辑/删除直接写入选定的可写日历，可设置原生提醒。没有授权时，保留原 localStorage 个人日程；用户可逐项幂等迁移，写入成功后才移除本机副本，失败项保留。

## API 与 MCP 契约

桌面通过唯一 allowlist API `window.pywebview.api.invoke` 暴露以下操作。外部 AI 通过 stdio MCP 使用同一 NativeCalendarService。没有另开无认证 HTTP 服务。

| 操作 | 用途 |
| --- | --- |
| native_calendar_status | 支持状态、授权、启用状态、变更代数 |
| native_calendar_connect / disconnect | 桌面连接授权或停止共享，不删除事件 |
| native_calendar_calendars | 系统日历及只读状态 |
| native_calendar_events | 带时区的起止查询，最长一年、最多2000项，明确截断 |
| native_calendar_get | 按事件ID读取最新内容和revision |
| native_calendar_save | 创建或修改，支持标题、时间、时区、全天、备注、地点、提醒 |
| native_calendar_delete | 删除指定事件 |

外部 MCP 客户端使用安装应用的 stdio 入口，保持同一应用身份：

```json
{
  "mcpServers": {
    "sjtu-learning-assistant": {
      "command": "/Applications/SJTU Learning Assistant.app/Contents/MacOS/SJTU Learning Assistant",
      "args": ["--mcp-stdio"]
    }
  }
}
```

开发环境也可用 `python -m sjtu_learning_assistant.mcp_server`，但独立 Python 进程的系统权限不等同于安装 App 的权限，不能用它替代 App 身份的原生验收。

MCP 不提供 connect/disconnect，须先在桌面启用连接。综合助理与截止教练具备原生日历工具；其他助理按 allowed_tools 控制。MCP tools/list 正确区分读写，日历工具错误不会绕过权限。模型不得从课程资料中推导写入授权，只按用户明确指示改变日程。

更新/删除必须带最新 revision，发生冲突重新读取。重复日程须带 occurrence_start 标识本次，span=this 默认只改变这一次；span=future 需要用户明确指定后续全部。当前接口没有创建重复规则、邀请参会人或修改提醒事项 Reminders 的功能。EventKit 不提供跨客户端原子 compare-and-swap，版本检查用于发现已发生的外部修改。

写入必须带唯一 UUID request_id，重试复用；SQLite 序列化桌面与MCP写入，记录幂等响应。创建事件附带请求关联URL，用于恢复 EventKit 已写入但本机事务未完成的请求。跨进程共享连接配置；断开后 AI/MCP 写入同样被拒绝。
