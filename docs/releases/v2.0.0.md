# SJTU Learning Assistant 2.0.0

完整界面迭代版。继续使用 React + TypeScript、Python 与 pywebview，接回真实接口，保留账号配置、同步状态、草稿、资料原件和编译检查点。

## 本版更新

- 按审阅原型重建全部页面与独立 CSS，稳定品牌及导航宽度，主要按钮采用黑白灰。
- 日程支持日／周／月、冻结全天区、局部 24 小时时间轴、点击创建、紧凑编辑、午夜截止全天展示。
- Mac EventKit 原生日历、桌面 API 和 MCP 共用读写服务；显式完整访问授权、冲突检测、幂等迁移、系统提醒和双向回读。
- 仅保留综合助手与资料库助手。综合助手可使用已启用的外部 MCP；资料库助手禁止外部服务、脚本执行和文件写入。
- 外部 Skill 支持 ZIP 原结构导入，保留 SKILL.md、README、scripts 与资源；内外技能分栏、启用开关、对话多选附件，配置在悬浮窗口展开。
- 标准 MCP JSON 导入支持 stdio、Streamable HTTP、SSE、工具发现和逐服务／工具权限。DuckDuckGo 上游拦截显示真实错误，不把“未返回结果”当作关键词不存在；可另外配置搜索服务。
- AI 输入与正文对齐，用户消息右对齐，单发送／停止按钮、任务补充、草稿及附件保留。
- 文件修改提议使用独立确认卡片，文件与状态分层，差异按需展开，左侧放弃、右侧确认写入；失败可重试，操作中阻止重复提交。
- 概览今日日程与日历页共用 Apple 日历读取，包含晚间、全天及跨日安排；系统修改后自动回读，读取失败明确提示并可重试。
- 视频主画面固定 16:9，PPT 悬浮与主视角切换，控制条在画面内；字幕位于画面下方，逐段时间标签支持定位。
- 课程资料和知识库按文件管理器浏览，左侧目录、右侧直属文件，点击／空格悬浮预览，Esc 关闭。Markdown、PDF 可阅读，PPTX／DOCX采用已有结构化内容预览并保留本地打开。
- 云盘固定顶部传输与选择工具栏，多选、下载、取消时不挤动列表；保留实际进度、续传与文件操作。
- 移除教师／助教成绩管理、花名册和批改入口及相关桥接权限。

## Windows 日程实际范围

| 能力 | Windows 2.0.0 | macOS 2.0.0 |
| --- | --- | --- |
| 应用内个人日程与日／周／月查看 | 支持，本机保存 | 支持 |
| 个人日程导出 ICS | 支持，Windows 日程配置浮层内手动导出 | 使用已有 Mac 日历路径 |
| 学校公告／作业截止系统通知 | 保留已有通知能力，需要 App 运行 | 保留已有通知能力 |
| 个人日程系统提醒 | 在导入 Outlook 后由用户设置 | 连接 EventKit 后支持 |
| 系统日历双向同步与 AI 原生日历写入 | 尚未接入，相关原生调用返回不支持 | 授权后支持 |

ICS 是导出时的快照，不是自动同步。重复导入的合并行为由 Outlook 决定；应用不会通过导出自动创建提醒。定时事件使用 UTC 保留实际时刻，全天事件使用本机日期与排他结束日，中文文本转义并按 UTF-8 字节折行。

导出通过桌面桥接保存到下载文件夹，不依赖内嵌浏览器的网页下载权限，也不弹出保存窗口；同名文件自动编号，保留已有文件。

Windows 旧 Mail／Calendar／People 已结束支持，后续采用 Microsoft Graph 委托授权连接 Outlook 日历，不依赖旧系统日历。实现双向同步前必须注册 OAuth 应用、完成用户授权并实现 delta 增量、删除传播、冲突处理与令牌续期；本版不宣称已接通。

官方参考：[旧日历支持状态](https://support.microsoft.com/en-us/outlook/outlook-for-windows-the-future-of-mail-calendar-and-people-on-windows-11)、[Graph 权限](https://learn.microsoft.com/en-us/graph/permissions-reference)、[创建日程 API](https://learn.microsoft.com/en-us/graph/api/calendar-post-events?view=graph-rest-1.0)。

## Windows 打包与使用

1. Windows 10/11 x64；推荐安装器 EXE。便携 ZIP 必须完整解压，不单独移动 EXE 或在压缩包内启动。Windows ARM 原生包不在本版范围内。
2. 需要 Microsoft Edge WebView2 Runtime。安装器检测 HKLM/HKCU；缺少时提示官方安装入口，静默部署需预先安装。普通功能已内置 Python，无需另装运行环境。
3. 外部 MCP 与 Skill 脚本的启动程序属于用户扩展依赖。`uvx`、Node/npm、Python 需自行安装或在配置中提供完整可执行文件路径；不把冻结 App EXE 当作 Python 解释器。
4. Windows Skill 使用 `python`／Node；`.sh`／`.bash` 明确拒绝直接执行，可使用 Python／JavaScript 版本，或另行配置 WSL MCP。包内 Windows 保留名称、尾随点／空格、特殊字符及大小写重复路径在解压前拒绝，不改写原包结构。
5. 命令与参数分开配置，中文及带空格路径不通过字符串拼接执行。优先短安装路径；长路径 manifest 仍受扩展程序和用户系统策略约束。
6. 安装为用户级，用户数据与凭据目录独立于安装目录。升级保留数据；macOS EventKit／PyObjC不进入 Windows 包，Windows 包包含 tzdata、PDFium、前端、MCP 客户端及 YAML 支持。
7. Mac 包为 Apple Silicon DMG，未做 Apple 公证；Windows 包未做商业代码签名，首次启动提示按系统规则处理。

## 发行验收

Mac 与 Windows 从同一不可变提交构建。保留完整测试、许可证与秘密扫描、固定 LGPL FFmpeg 源码和依赖校验、可执行文件 manifest，以及真实安装包前端／桥接启动检查。新版启动检查必须识别 2.0 页面结构，旧壳或空页面不能通过。

GitHub 只有全部发行门禁成功后才公开三个附件：macOS-arm64.dmg、Windows-x64-Setup.exe、Windows-x64-portable.zip。内部校验记录及校验和由同次构建验证，不作为额外公开附件。最终结果以对应 GitHub Release 工作流为准；CI 原生启动通过不等同于所有 Windows 用户环境和真实账户接口都已人工验收。

安装包另执行实际 MCP 子进程协议验收：工具发现、只读标注、UTF-8 调用及无效参数拒绝。Windows 无控制台程序仅在明确的 MCP 模式恢复父进程传入的管道，不弹出控制台；普通桌面启动不修改标准流。此验收不访问互联网，联网成功与否仍取决于用户网络和上游服务。
