# 2.0.2 本地检索质量补丁

2026-11-28。本轮完成本机更新，GitHub 正式发行仍为 v2.0.0；未移动历史标签、推送工作分支或新增远端发行。模型仍为 deepseek-chat。

## 修复范围

用户反馈的人物查询有两处问题：在线追问继续预读取课程资料；Bing 返回姓氏字典页时仍被当成有效人物搜索，模型继而推断身份或没有公开资料。

- 在线搜索、联网查询、再试试等短追问从最近的用户原文继承对象。在线轮次移除旧助手回复、邮件、页面和附件上下文，并在工具执行及缓存读取前重新核对来源权限。
- 普通姓名查询优先公开网页；在线课程、课件作者等本地学习问题保留原逻辑。用户明确同时查询本地和网络、或保存到工作区时，继续使用原混合能力。
- Bing 支持 exact_phrase，短中文专名加引号；按完整短语排除无关标题和摘要。匹配字串只用于定位来源，不足以证明身份。零匹配不能证明人物不存在、没有公开资料或就是用户本人。
- 搜索失败或短追问无有效匹配后，本轮停止同源换词；允许其他已启用来源。网关要求历史工具消息携带定义时，使用 tool_choice=none 结束搜索，保持调用配对。
- 短联网追问限制为 1200 输出 token，不自动长文续写。结构化 MCP 条目按实际数量展示，零结果保留实际状态。
- 已启用的内置 Bing 服务重新读取工具定义；启用状态、权限和工具选择保持。已关闭服务继续关闭。

## 真实验收

使用安装后的应用身份、真实 deepseek-chat 和真实已启用 MCP，独立 SQLite 快照及合成旧邮件标记执行“先问人物，再追问在线搜索”。检索对象在交接记录中以 周济睿 表示；不导出原邮件或模型完整请求。

最终结果：11.89 秒、2 次模型请求、一次 Bing 搜索、0 次本地工具、0 次自动续写、0 次日历写入。合成旧邮件标记没有进入任何模型请求或最终回复。最终回复 101 字，说明本轮没有有效证据，未再推断人物是用户本人或没有公开信息。完整脱敏结果见 v2.0.2-search-quality-evidence.json。

扩展停止、补充、HTTP 中断、AI/MCP 回归 164 项通过、2 项子测试通过。最终定向回归 89 项通过、2 项子测试通过，覆盖同源无匹配停止、其他来源保留及冻结优化下验收条件仍生效。前端没有修改，复用已经验收的 React + TypeScript 构建。签名、Mac 验包、FFmpeg 和打包 MCP 门禁通过。

安装后首次验收曾发现流式响应格式不兼容，且旧验收逻辑错误标为成功。该次记录不算通过：已修复网关的工具定义兼容，并将冻结构建中会被移除的 assert 替换为显式错误检查。最终验收直接读取任务 chat_result，核对助手消息角色和真实工具记录。

## 本机更新

暂停新 AI 请求、排空在途任务、正常退出旧应用后备份并替换；AI 开关已恢复，应用已重新打开。程序二进制与验收构建一致，76 个前端资源哈希一致，70006 个学习文件核对零变化。旧应用、SQLite 和设置保留于本机版本化备份。Apple 日历只读验收通过，没有新建、修改或删除日程。

本轮使用原工作分支，保留用户两个设计文件的未提交修改。工程交付不包含数据库、配置、密钥、邮件原文或付费响应快照。

## 剩余范围

Bing 本轮仍未取得有效人物匹配；DuckDuckGo 的机器人检测或限流没有消失。修复应用流程不能代替搜索源覆盖率或提高模型本身能力。需要后续接入更可靠的搜索源、可信原文读取及更强工具模型，再分别进行真实验收。Windows 2.0.2 未在真机重新打包验收，不将 Mac 本地结果解释为跨平台发布完成；原 Windows 本机日程与 ICS 能力保留。
