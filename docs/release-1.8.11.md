# SJTU Learning Assistant 1.8.11

本补丁版修复正常公网邮件图片被固定来源白名单拦截的问题，不覆盖任何历史 Release 或安装包。

## 修复范围

- 支持普通公网 HTTPS 邮件图片与协议相对图片地址，保留受控资源地址并支持重复清洗；不再只允许两个交大域名。原始图片地址不会直接写入浏览器 DOM。
- 打开邮件时自动匿名加载支持的图片，可按邮件暂停、重新加载；暂停后的旧请求结果不会回写图片。界面说明发件方可能获知访问记录，不发送邮箱、Canvas 或浏览器凭据。
- 每次请求与跳转核对全部 DNS 地址，拒绝私网、回环、链路本地、保留地址与不安全 IPv6 过渡地址；连接锁定本次验证的 IP，同时保持原域名 Host/SNI 与 TLS 证书验证。不使用环境代理，不保存跨请求 Cookie，不复用不同域名同 IP 的 TLS 连接。
- 维持重定向、响应大小与读取时间限制；核对有限 PNG/JPEG/GIF/WebP 文件头，拒绝 HTML/SVG、类型不匹配和无图片内容的响应。
- 邮件内容版本提升至 3，旧版本丢失的图片地址通过既有有界只读 BODY.PEEK 回填恢复；保留正文、已读状态与同步游标，不降级未来版本。旧邮件请升级后同步邮箱、重新打开。
- 原邮件明确标为 0×0 且无替代文本的隐藏计数信标不转成正文错误框；正常可见图片和替代文本保留。
- 保留 1.8.10 的通用 MIME 内嵌图片恢复、诊断隐私和邮件外框兼容修复；第三方邮件图片不能进入 Canvas 带凭据请求流程。

## 真实来源核验

22:26 截图对应前程无忧邮件中有 12 个原始图片地址，旧缓存版本 2 没有保留这些地址。通过只读 PEEK 取得来源后，11 张正文图片在 `img01.51jobcdn.com`、`fecdn.51jobcdn.com`、`img07.51jobcdn.com` 匿名请求成功，并通过 macOS 原生解码。剩下 `receiver.51job.com` 为无替代文本的 0×0 信标，返回内容不是支持的图片，不属于正文图片。

Windows CI/打包与平台参数测试不等于朋友 Windows 真机验收；朋友需升级本补丁后复测。没有调用 AI 模型或执行真实学习数据写入测试。
