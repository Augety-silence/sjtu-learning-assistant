## 维护方式

- 状态变更必须附commit、测试或运行证据；“写入日志”和“功能完成”分别记录。
- 先刷新main及工作目录实际状态；日志中的提交差距和本地冲突仅是带日期快照。
- 新想法沿用稳定ID，在新日期日志追加变更原因；不把旧测试数字当当前验收结果。
