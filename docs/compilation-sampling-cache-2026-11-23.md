# （2026-11-23）重复审阅拖慢知识库编译

问题：原始资料已经生成总结后，仍逐块对整份总结重复进行完整审阅，占用模型调用和输入 token。长资料分段生成原来串行执行。跨文件的相同请求也不能复用响应。

解决：

- 原文、原始字幕和篇幅目标不变：正文最多 5000 字符，编辑目标仍为原文约 30%。
- 自动课件普通分段改为确定性 20% 抽样，合并稿仍必审。字幕最终稿引用的原始分块必审，其他分块约 20% 抽样；生成仍完整处理全部原始字幕。
- 审阅聚焦事实、公式、必要条件与来源，省去措辞润色、重复算例核对。实际请求的意见最多 3 项、每项 120 字符，输出预约从课件原来的 2048 降为 1024 token，字幕从 7500 降为 1024 token。预约量不是实际消耗。
- 每份课件最多 3 个独立分段并行生成，合并依赖仍等待全部分稿。保留全局共享 10 RPM / 300000 TPM / 最多 10 在途请求，不增加每日调用上限。
- 新增同服务、同凭据摘要、同模型和完全相同请求的本机响应缓存；有效期 7 天、最多 256 条。JSON 字段顺序不影响身份；服务、凭据、模型、提示词、原文和输出上限变化都会隔离缓存。只保存响应及校验摘要，不保存密钥、提示词或原始输入。
- 原文固定置于请求前部，动态草稿/修复意见放后面，增加同源请求的公共前缀。上游是否提供前缀缓存仍取决于服务，没有把缺失的缓存 token 上报当作命中。
- 已付费检查点和通过的旧审阅继续复用，不更换提示词版本目录，不触发全库重编；抽样跳过的分稿不写“审阅通过”缓存。抽样结果明确记为 source-sampled。
- 并发调用计数、事务提交与清单写入加锁；暂停/退出信号传给分段线程，避免并行后遗漏取消。
