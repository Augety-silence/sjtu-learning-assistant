# 邮箱同步与跨设备诊断（诊断包 schema 2）

## 本次修复

- 桌面与后台同步记录 `sync-stages.jsonl`：启动、数据库、配置、Canvas、邮箱凭据、TLS 初始化、IMAP 连接/登录/选箱/UIDVALIDITY/检索/读取、持久化及正文回填。
- 日志保留 UTC 时间、运行 ID、阶段、耗时、结果、异常类型链与数值错误码，不记录异常参数、账号、密码、邮件正文或 HTTP 响应正文。
- 导出包增加 `status/sync_details.json`，按来源分别保留最近记录、最近失败，以及 inbox/run 状态和时间。大量 Canvas 成功记录不会挤掉邮箱证据。
- 收集桌面日志的时间、级别、代码位置、异常类型；原始消息和源码行不导出，防止服务端正文和凭据进入诊断包。
- 收集新旧同步日志及上一份轮转文件；manifest 明确记录缺失、不可读、链接拒绝或已过滤状态。旧日志缺失不会伪装成已经采集。
- ZIP 白名单、单条目 256 KiB、总解压 768 KiB、ZIP 1 MiB 上限不变；每份日志尾部最多 96 KiB。日志和临时文件保持私有权限，日志写入失败不阻止同步。
- Canvas 的已知网络/归档异常不再跳过邮箱；整轮仍返回非零退出码并记录 Canvas 失败，不把部分成功包装成全部成功。
- 后台邮箱同步仅使用已保存的当前账号凭据；不可读或缺失时给出可诊断错误，不等待隐藏的密码输入。
- IMAP 同时使用系统信任与随包 certifi CA，保持证书校验和主机名校验，不依赖构建机 OpenSSL 默认证书目录。

## 可移植性结论与边界

打包后的同步命令使用当前 `sys.executable --background-sync`。`.venv` 和项目脚本仅用于非打包开发模式，不是成品 App 的必需路径。

数据目录在运行时按当前用户解析：macOS Application Support；Windows 使用 platformdirs 解析 AppData，并支持显式 `SJTU_APP_SUPPORT_DIR`。环境覆盖是否设置会以布尔值进入诊断包，不导出完整路径。

凭据属于当前操作系统用户的安全存储，不随 App 分发。每位使用者必须在自己的电脑和系统账号下保存自己的凭据；“已配置”不证明登录成功，也不证明后台进程获得读取权限。

本次新增用例覆盖了模拟其他用户目录、Windows 重定向路径、打包入口、系统 CA 为空、网络/TLS/认证/选箱/检索/启动失败、Canvas/邮箱隔离、日志权限、轮转、缺失、恶意载荷和敏感内容排除。模拟 Windows 路径不等同于 Windows 真机验证。

用户提供的旧诊断包只有状态摘要，无法恢复当时缺失的错误阶段；以上改动不证明另一台电脑的具体故障已经修好。

## 受影响电脑的复验步骤

1. 安装包含本次提交的新构建；不能继续使用旧二进制期待新增日志。
2. 在该电脑的设置中确认自己的邮箱账号和凭据，点击同步并等待失败或完成。
3. 立即导出诊断包。检查 manifest 的 `schema_version` 为 2，并检查日志采集状态。
4. 排查 `sync_details` 中的来源/失败时间，再按相近时间和运行 ID 查看阶段日志。先区分 Canvas 失败、凭据读取、连接/TLS、认证、IMAP 协议、数据库提交，不先假定密码错误。
5. 同步只覆盖 INBOX；初次默认最近 100 封，随后 UID 增量。历史邮件不全应作为同步范围问题单独处理，不能通过删除数据库或游标“修复”。

本次验证不运行真实全量邮箱同步、不修改远端邮件状态、不使用真实学习数据做写入、不调用付费模型。
