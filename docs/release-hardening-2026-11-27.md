## 跨平台缺陷与最小修复

### 1. Windows 文件锁
- 现象：恢复与预算台账在原生 Windows 上因缺少 `fcntl` 直接失败。
- 修复：Windows 使用 `msvcrt` 单字节区间锁，保证真实跨进程互斥；获取失败即拒绝，不退化为无锁。POSIX 继续使用 `fcntl`。
- 保留：确定性关闭、不可变响应哈希、只读清单、预约与预算上限均未放宽。

### 2. 目录同步
- 现象：Windows CRT 拒绝以目录句柄调用 `fsync`，触发权限错误。
- 修复：文件 flush 与 `fsync` 仍为强制项；目录同步仅保留在 POSIX。封存、只读、哈希校验不变。

### 3. 取消与即时补充
- 现象：观察线程已收到中断，但请求线程仍阻塞在定时 `recv/select`；Windows 不保证 `shutdown` 唤醒读取。
- 修复：观察线程仍只执行一次 `shutdown`；请求线程按 100ms 有界轮询读取，并保留原始每次读取截止时间，不重试 HTTP。
- 连接复用：在连接归还池之前恢复请求专属的读取包装，避免已取消请求的回调影响后续复用连接；已收到的付费内容与 usage 继续保留。
- 未放宽：1.5 秒回归断言、模型预算与审批边界。

### 4. 测试夹具
- 中文 Markdown 夹具在 Windows 默认代码页下写入失败：全部改为显式 UTF-8。
- 生命周期夹具不再把伪索引传入真实原生前端加载器，也不写真实应用数据。
- 不跳过失败子集，不隐藏警告。

### 5. 发布脚本
- Windows 本地代码页把 `gh` 的 UTF-8 输出按 cp1252 解码，遇到中文发行标题即中断：改为捕获字节并显式 UTF-8 解码。
- 草稿创建后立即回读列表存在最终一致性延迟，曾造成假失败与同 tag 重复草稿：改为以 REST 创建响应为权威结果。

## 发布门禁

- 标签与提交不可变，同一提交双平台原生构建。
- 原生证据必须来自同一 run 与同一 attempt，仓库、来源 SHA 与 actor 一致。
- 公开附件仅三个；校验和、启动证据、许可证与秘密扫描保存在内部构建产物，不作为额外附件。
- 只有全部原生任务成功、下载后的三个二进制与内部证据一致、草稿元数据重新核验通过，才允许草稿转公开。
- 失败或跳过任何原生任务即 fail closed；不移动已有标签，不覆盖已公开发行。

## 流水线提速

- 新增 `windows-preflight`：不打包、在同一不可变提交上跑全量 Windows 测试，Windows 专属问题约 10 分钟暴露。
- 打包后的重复全量测试已移除；同一 SHA 的测试只在预检执行一次，打包后的真实启动与来源校验保持不变。
- 非源码原因的失败优先在同一 run 全量重跑，不发新版本；注意证据校验要求同 run/attempt，不能用 `rerun --failed` 拼接两套证据。
- Mac 与 Windows 作业本来就并行；macOS arm64 runner 可能因容量排队。
