# 本地验证代理的合并门禁

本文件授权的是流程边界。云端不能填写本机验证为通过或执行 merge。

## 入口
收到同一 Draft PR 的最终 head SHA、任务 commit 表、CLOUD_DELIVERY_REPORT 和 CI/artifact 链接。
先获取最新远端，固定待验 SHA，并记录 main 当时 SHA。使用干净隔离 checkout/worktree，不切换或覆盖原有脏工作区。
没有可靠的 CI、对应源码或 artifact 则先补证据。若 main 前进或后续有修正，形成最终集成 SHA 后重新做受影响检查。

## 门禁
1. 独立代码审阅：分题范围、恢复/取消/上限、source-only保留、状态优先级、缓存身份与无敏感数据。
2. 同 SHA 相关与全量回归；不将旧日志算作该 SHA 结果。
3. 本机已授权范围内的真实字幕/配置模型验收。独立 DB/settings/transcripts/memory；正常进程内 Keychain 读取，不导出；调用预算明确。区分处理完成、质量门和合法内容存疑；不得强制 PASS。
4. 同 SHA 干净 Mac 构建或已验证的 CI artifact，核对全部必要第一方模块/前端资源、版本、架构与签名。不要直接运行会清理原 checkout build/dist 的旧脚本。
5. 独立数据根启动准确候选 App，核对执行路径/版本；验证真实加载与播放、无需手动启动整理、分段提前可用、时间同步、seek、倍速、切换/取消、恢复与耗尽提示。不能以静态截图或签名替代。
6. 确认真实学习数据未被污染；验收记录关联 exact SHA 与候选身份。需要正式安装时采用可回退方式，实际重开正确安装路径再核对。

## 合并
云端只有合成/构建通过不能合并。
全部必要本地门禁通过后，重新确认 PR head 与已验 SHA 完全相同、CI成功、无新增未审提交；若不同立即停合并并重新验证。
由本地验证代理记录脱敏报告/PR评论，转 ready，再用带匹配 head SHA 的合并操作保留分项 commits；不 squash、不强推、不提前开auto-merge。
真实隐私资料、机器路径、凭据与模型原回复不写公共报告。若本地能力或环境不足，明确阻塞并保留 Draft。
