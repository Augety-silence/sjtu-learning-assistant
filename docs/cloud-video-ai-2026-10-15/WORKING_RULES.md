# 本次工作规则

## 授权与数据
只修改本仓库的本次任务范围；不得改其他仓库、仓库权限、分支保护或自动发布设置。
允许在工作分支 commit/push 并更新本次 Issue/Draft PR。禁止云端 merge/auto-merge、undraft、tag、Release 或生产部署。
不读取、不索要、不上传真实字幕、学习资料、数据库、日志、Keychain、签名证书、校园帐号或模型 API key。依赖下载与 GitHub 操作的正常认证不代表可以导出凭据。
所有“真实验收历史”只是事实背景，不能伪装为本次云端已经运行。

## 实施与协作
从固定源码基线的集成分支开始，先看已有代码；不要重写已完成的自动准备/同步功能。
每题一个可审阅的独立 commit，必要修正可补同题 commit；不混 unrelated 格式、版本号或全站样式重构。
不 git reset --hard、clean、强推或删除他人分支/提交。合成回归在临时目录，不向默认用户应用目录写数据；不改变 HOME 以隔离测试。
多代理按任务文件所有权划分；C1 和 C3 共用 service，必须串行。
未知工具名用本平台等价方法替代，不依赖 Codex、Claude、Gemini CLI 或 MCP。

## 事实与结果
JSON/source-only 修复必须有程序可验证的保留约束；不能只靠提示词承诺。
内容需核对与技术失败分开，cache 复用必须验证当前 hash/model/prompt/memory 绑定。
不清理真实错误来消除黄色状态，不提升 confidence，不弱化质量门，不改写题面伪装课堂原题。
单元测试、合成全链、干净构建、真实模型、原生界面和正式安装是不同证据。
报告实际命令、退出状态、执行平台和 tested SHA。未执行的检查如实写未执行，不伪造截图、签名或 CI 链接。

## 完成边界
云端完成 = 分题 commits + 相关回归 + 完整现有 CI + 可审阅报告。
项目完成 = 本地代理对最终同一 SHA 完成代码、真实模型、Mac 包和原生界面验证，再由其合并。
如后续改了 head，必须重新验证受影响范围，不能沿用旧 SHA 的本地通过结论。
